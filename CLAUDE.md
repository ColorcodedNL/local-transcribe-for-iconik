# Working on Local Transcribe for Iconik

Notes for an AI coding session in this repo. The README says what the app does; `docs/RELEASING.md` is the release procedure; `docs/SBOM.md` lists what ships.

## Layout

- `app/` is the app. Everything in `CODE_FILES` in `tools/make_manifest.py` can go out as a small signed code update. `main.py` and `app_shell.py` are the fixed shell: they start the app and verify updates, and only change with a new dmg and a higher `SHELL_VERSION`. Touch them only when there is no other way.
  - `transcribe.py`: the fixed entrance to the engine parts below, and the command line. Holds `APP_VERSION` (the build scripts read it there). Reading `transcribe.X` gives the live value from the part where X lives; `transcribe.X = ...` sets it in every part that knows X, so tests and `serve.py` keep working. New code imports the part itself
  - `base.py` (names, paths, log, progress, language, errors, config), `iconik_api.py` (login, client, ISG mounts, find the media file), `audio.py` (ffmpeg, track analysis, waveforms), `speakers.py`, `filters.py`, `whisper_mlx.py` (the first engine: Whisper on MLX, pinned model), `engine.py` (the list of engines and the fixed form every engine has; nothing outside `whisper_mlx.py` touches MLX), `pipeline.py` (one job from start to end). A part only imports from parts earlier in this order; `tests/test_split.py` checks that
  - `settings.py`: every setting in one schema (key `group.name`, type, default, limits, label and help in Dutch and English). `settings.get(key, instance)` reads with the default, `settings.put(key, value, instance)` checks and saves; `instance` (`iconik-<6 hex>`) only counts for a connector's settings, and without it there must be exactly one instance of that kind (otherwise `InstanceError`, never a silent pick). A later part (an engine, a connector) adds its own setting with `settings.register`, a connector its kind with `settings.register_integration`. Comes right after `base` in `PARTS`. `config.json` is version 2: `general`, `transcription`, `refine` and `integrations.<id>` with a `type` (id `iconik-<6 hex>`; `settings.add_integration(kind)` makes another). A flat file of 0.6 is converted on first read and kept as `config-0.6.json`. Code never reads `config.json` itself; only `base.app_language` does, because it comes before `settings`. Tests read with `settings.stored(key)`
  - `system.py`: what differs per operating system, under fixed names (paths, process memory, the room check for auto transcribe, mounted volumes, a folder picker, keeping awake, opening a link, start at login, the computer name). `platform_mac.py` is the only implementation; a Windows or Linux one gets the same names and a line in `IMPLEMENTATIONS`. Outside `platform_mac.py` and the Mac shell (`app_main.py`, `main.py`, `app_shell.py`) nothing calls macOS directly; `tests/test_split.py` checks that
  - `connectors.py`: the fixed form of a connector (capabilities `source`, `write_back`, `read_back`, `queue`, `auto_scan`, its own `SETTINGS`, the functions per capability). The app only calls a connector through `connectors.call(instance, function, ...)` with plain data (JSON) in and out, so a connector can later run as its own program. The connector gets a `Host` from the app (settings of its instance, noted facts, secrets, log, language, `may_take`). `keychain.py`: secrets per instance (`<instance>:<name>`), read once and kept in memory. Neither is in `PARTS`. The Iconik login is `<instance>:login` (`iconik_api.load_login(instance)` and the rest of the login take the instance; without it the only Iconik). The item of before step 5 (account `login`, or the old app name) moves once to the only Iconik and is deleted; `settings.note(instance, "keychain", "moved")` keeps it from coming back, and logging out retries a delete macOS refused
  - `iconik.py`: the Iconik connector in that form (`status`, `open`, `find_media`, `write`, `read`, `poll`, `report`, `beat`); `IconikConnector` does the work on a client from `iconik.client(instance)`. `iconik_queue.py`: the queue in Iconik (fields, claiming, heartbeat, reporting, pause). Its fields and view are keys in the customer's Iconik and never change with the app name. `worker.py`: the loop over every instance with a queue, and the name of this Mac; old names (`worker.Queue`, `worker.state`, ...) still point into `iconik_queue`. The Iconik settings are `iconik_api.SETTINGS`, registered when `iconik_api` loads
  - `local_files.py`: local files as a source, in the connector form (`status`, `open`, `find_media`, `write`, `read`). Not an integration but part of the app: `connectors.BUILTIN`, the one "instance" is `local`, it is never in `config.json` under `integrations` and its settings are the app's own group `files`. An item is `local:<fingerprint>`: sha256 over the size and the first, middle and last MiB (chosen 26 November after measuring on the ISG: SMB gives no volume ID, the fingerprint costs about 60 ms per file there, reading a whole file takes minutes). `local-files.json` (`base.LOCAL_INDEX`) keeps per fingerprint the paths that were added and which still wait for a transcript; a copy elsewhere gets the transcript the Mac already has, without transcribing again. The transcript is `clip.transcript.json` next to the media or in one folder (`<folder>/<volume>/<path>`, `system.volume_place`); `clip.mxf.transcript.json` when another file with the same base name already has one. A file in another format, or one that cannot be read, is never overwritten. The file next to the media holds only the media's file name, never a path. Everything the app writes next to the media is in `sidecars.json` with its hash (`subtitles.record`)
  - `items.py` (a part, right after `settings`): the identity of an item, `<source>:<key>` where the source is an integration instance (`iconik-<6 hex>:<asset>`) or `local` (`local:<id>`). Everything the app keeps per item lives in a folder per source (`transcripts/<source>/<key>.json`, the same in `waves/` and `refine/`); `items.migrate` moved the loose files of before step 4 there once. Iconik calls take `items.asset_id(item)`, never the item
  - Several Iconiks: everything per Iconik takes the instance (`serve.bits(instance)`, routes with `?instance=`). An Iconik environment is known by its `system_domain_id` (noted per instance after login), the same on every Mac; the instance ID differs per Mac. Anything shared between Macs (the buttons, the queue) uses the domain, never the instance ID. Buttons always carry `?lt_domain=<system_domain_id>`; a button without it is replaced at the next check. A second integration to an environment that is already linked is refused: a client ID another integration already uses when it is entered (`serve.same_client`), otherwise after login (`serve.refuse_double`); `items.same_environment` stays as the safety net when the domain could not be fetched. A name per integration in `iconik.name` (empty: "Iconik", "Iconik (2)", ...). + and − in Settings: `serve.add_integration`, `serve.remove_integration` (with "also from this Mac" and "remove the buttons from Iconik")
  - `jobs.py`: the job list, a `Job` per row with one lock for the list and every field (change through `job.set`), and `jobs.json` with a format version (2: `item` per row; a file without version is read as asset IDs of the one Iconik)
  - `serve.py`: the local receiver on 127.0.0.1:8765. `ui.html`, `refine.html`: the window. `refine.py`: the editor's backend. `transcript.py`: the own transcript model. `subtitles.py`: subtitles as a second layer that someone makes on purpose in Refine (dividing by rules, fitting, warnings, .srt and .vtt files)
  - `app_main.py`: the Mac app around it (window, menu bar, links from Iconik). `updater.py`: code updates
- `scripts/`: build scripts, `probe_imports.py` (used by the build) and `probe_cluster.py`. `tools/`: signing, manifest, test helpers, `probe_tracks.py` and `request_transcript.py`. A one-off probe is removed once its finding is in the code or the docs; it stays in the git history. `tests/`: one script per area, each prints OK or FOUT lines and exits non-zero on a failure.
- Code comments, log lines and test names are Dutch. Docs, commit messages and release notes are English. Every text a user sees exists in Dutch and English through `transcribe.L(dutch, english)` or the `TEXT` table in the html files.

## Rules that came out of earlier work

- New files in `app/` that the app needs go into `CODE_FILES` (and a new engine part into `PARTS` in `transcribe.py`), or a code update leaves them out. Code updates only know flat file names, no folders.
- Code in a code update also runs on apps with an older shell. Reach for something new in `app_shell` with `getattr` and keep a fallback.
- Every route is one entry in `ROUTES` in `serve.py` (the `@route` decorator), with its access as properties: `session` (cookie of the app's own window, or the listener key; off only for what comes from outside), `protected` (changes something: POST only, with the `X-Local-Transcribe` header) and `kind`. `/api/v1/` is reserved for a documented API. A new route also goes into the expected table in `tests/test_routes.py`. New window behaviour gets a step in `tests/test_e2e.py`, or in `tests/test_refine_window.py` for Refine.
- Never overwrite a transcript from another source or a correction made in Refine.
- The line break and the warning level of a subtitle are calculated twice with the same choices: `subtitles.layout` and `subtitles.warnings` (the file and the counts) and `layoutLines` and `check` in `refine.html` (the screen). Change one, change the other; `tests/test_refine_window.py` compares them.
- Subtitles only exist when someone makes them (+ Subtitles in Refine). Nothing writes a subtitle file by itself, and a file the app did not write, or that changed afterwards, is only replaced when someone picked that path in the save panel.
- No own machine names, paths or account names in the app, tests, messages or screenshots: use generic terms such as "opslag (ISG)".
- Tests never touch the real keychain, config or support folder. Code that tests replace by name stays reachable under that name (for example `resources.memory`, `transcribe.mount_reachable`), also after it moves.
- No special builds for the developer's Mac: test builds are ad hoc signed like releases, so they behave like what users get.
- Measure on real material before building on an assumption.

## Tests

- All: `bash scripts/run_tests.sh` (needs `uv`; the browser test needs Chromium once: `uv run --no-project --with playwright playwright install chromium`, or `LT_CHROMIUM=/path/to/chrome`).
- One: `uv run --no-project --with pynacl --with requests --with numpy --with huggingface_hub python -B tests/test_worker.py`
- The tests replace MLX, torch and the keychain, so they run on Linux too. What they cannot show: the real window (WebKit), the menu bar, the build scripts and a real job. Those need a build on a Mac: `bash scripts/build_bundle.sh && open "build/Local Transcribe for Iconik.app"`, log in `~/Library/Logs/Local Transcribe for Iconik/serve.log`.

## Working through a remote session

- When the repo is reached through a bridge that cannot delete files, edit in place (read, replace, write) and leave git commits, merges and pushes to the owner in their own terminal: git needs to remove its lock files.
- Building, signing and releasing happen on the owner's Mac. Publishing is always the owner's own step.
